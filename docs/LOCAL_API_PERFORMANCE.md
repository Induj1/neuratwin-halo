# Local HTTP workload rehearsal

Run `python scripts/rehearse_api_performance.py` from `round2`. The script launches one disposable Uvicorn process on an automatically selected loopback port. It filters application/cloud credentials out of the child environment, sets a temporary SQLite path and disables physical control. It does not load `.env`, open a serial port, import hardware measurements, or contact Supabase.

The fixed workload creates 12 independent industrial simulations, using at most four concurrent HTTP clients. Each run performs ten state-changing actions, reads back after each action, and exports its own report. The 264 measured requests comprise 12 creates, 120 actions, 120 reads and 12 exports. Unique profiles, input levels, revisions, elapsed simulation time and exported run identities are checked during execution. After stopping the server, the script checks all persisted runs and verifies zero physical frames and commands.

The script writes [the current measurement](../reports/local-api-performance.json). It records overall and per-operation p50/p95/p99 latency, HTTP status/error counts, elapsed time, offered concurrency, Python/library versions, CPU/memory metadata without host identity, and source hashes captured before the server starts. A source change during measurement prevents a passing result. Percentiles use linear interpolation; startup readiness and final diagnostics are excluded. Client JSON checks are outside individual request timers but inside total workload time. The lifecycle-owned analysis-recovery worker remains enabled during this rehearsal.

The current run completed all 264 requests with HTTP 200 and zero request/run errors. Overall p50 was **72.496 ms**, p95 **333.360 ms** and p99 **370.551 ms**; the 120 state-changing actions had p95 **347.574 ms**. Total workload time was **14.056 seconds**. All 12 persisted runs and exported reports passed the isolation checks. The numerical benchmarks and the 334-test release suite had completed before measurement; other system activity was uncontrolled. These are observed results for the report's pinned source hashes, not guaranteed response times.

The previous successful measurement is preserved at [2026-10-08 19:26 UTC](../reports/local-api-performance-20261008T192652Z.json). Its production-source hashes precede the replacement-device recovery guard and must not be presented as a measurement of later sources.

This is one local reproducible workload, not a fleet-capacity or production-SLA claim. It does not measure remote database latency, WAN behavior, browser rendering, physical telemetry, queue-backlog contention, multiple application processes or simultaneous writers to the same run. There is no run DELETE endpoint, so deletion is not part of the workload. Latency has no invented pass threshold: the script passes on successful requests, state isolation and persistent evidence consistency. Repeat measurements may differ with other operating-system activity.
