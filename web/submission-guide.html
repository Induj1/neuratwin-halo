The contribution

Halo connects condition monitoring to accountable maintenance. It keeps the entire investigation attached to one asset and one clock: observe → freeze a prediction → reveal later data → compare actions → record follow-up → export the evidence. A prediction that loses to a simple baseline remains visible. Missing measurements cannot turn into a healthy state.

The industrial simulation, the physical bench and independent reference datasets have an explicit source selector. Switching views within an industrial case never substitutes a replay or another asset.

Where is the intelligence?

Physics provides an interpretable expected thermal response. Bounded parameter identification learns the oil rise and time constant from a reviewed healthy trace. Residual rules compare observations with expectation; constrained enumeration compares actions. These are explicit numerical methods.

Laya is an optional typed decision model. Its saved five-case evaluation abstained in all five cases, so it is not used as proof of diagnostic accuracy or as a protection controller.

What makes the result credible?

  • Predictions preserved before future data.
  • Same asset, source and clock across the main workflow.
  • Persistence baseline, missed faults and false alarms shown.
  • Rejects stale plans and conflicting writes.
  • Sensor faults and missing measurements remain visible.
  • Maintenance closure records later observations.

Run locally on a teammate’s laptop

Python 3.12+ and the dependencies in requirements.txt are needed. A fresh local rehearsal is separate from the configured cloud project:

python -m pip install -r requirements.txt
python scripts/run_local_demo.py
# Open http://127.0.0.1:8765/app#demo
# Stop with Ctrl+C. Does not load .env or open a serial port.

The launcher selects a separate SQLite file and binds to loopback. It cannot accept remote clients or silently fall back from a cloud outage. The numerical application works without Laya. A standalone visual fallback is at web/halo-fallback.html; it is a precomputed synthetic walkthrough, not a running model.

For the existing private cloud configuration use python -m uvicorn neuratwin.app:app --host 127.0.0.1 --port 8765 --env-file .env. Cloud hosting needs HTTPS, team membership and local-owner access disabled. A static Vercel guide is not the full application backend.

Questions a technical judge may ask

“Is this a real distribution transformer?” The industrial mode represents one using an illustrative model. The small physical transformer demonstrates sensor acquisition and load response. Neither is claimed to validate field failure prediction.

“Can the model lose?” Yes. Forecast records show when persistence performs better. The independent test misses 8 of 24 fault episodes; mild faults are an explicit limitation.

“Can you predict remaining life?” Not from these sensors and datasets. Any ageing display is a declared hypothetical thermal-exposure calculation, not actual insulation life.

“What does CPRI’s spreadsheet prove?” Its 12 examples support acceptance comparisons; they are not a longitudinal fault-labelled training set.

“Will this operate equipment?” Simulation commands cannot target physical relays. Physical operations require commissioning, calibration, fresh data, permissions and independent protection. K4 stays locked.

“What is still needed?” Qualified hardware review, measured calibration/acceptance records, an asset-specific thermal reference and independent real-fault evaluation. Live Telegram/NFC delivery also needs device/service testing.
